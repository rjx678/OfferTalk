# OfferTalk求职爆料小程序 - 作品展示帖

---

## 【微信小程序·求职工具】OfferTalk：一站式研发岗求职爆料社区

---

### ①摘要

面向计算机应届生、校招求职者、社招跳槽研发工程师，在求职信息分散、真伪难辨的场景下，提供结构化面经Timeline、结构化薪资爆料、公司真实评价的一站式社区平台，目前已完成微信小程序+SpringBoot后端完整项目交付。

---

### ②真实场景与需求

**目标人群：**
- 计算机专业应届生（校招求职）
- 社招跳槽的研发工程师
- 互联网从业者（了解市场行情）

**痛点描述：**
1. 面经信息分散在牛客网、脉脉、小红书、OfferShow等平台，信息碎片化，难以系统性准备面试
2. 薪资信息不对称，候选人对市场行情缺乏参考，入职后容易出现薪资倒挂
3. 公司评价来源单一，难以全面了解目标公司的真实职场环境
4. 现有平台信息良莠不齐，缺乏真实度评估机制

**现有做法：**
- 手动搜索多个平台收集面经 → 效率低、信息不完整
- 通过社交媒体打听薪资 → 信息滞后、不够客观
- 看公司评价决定是否投递 → 缺乏量化指标
- **为什么不够：** 成本高、信息不完整、缺乏结构化整理、无法横向对比

---

### ③作品介绍

**产品定位：** 垂直互联网研发岗位的轻量化求职工具社区

**核心功能：**

**前端（微信小程序）：**
- **首页信息流：** 卡片流式布局，支持校招/社招/实习分类切换，多维排序（最新/热度/薪资/真实度）
- **公司大全：** 按字母排序的公司列表，支持行业筛选和快速查找
- **面经详情：** 完整Timeline展示（投递→一面→二面→三面→HR面→Offer）
- **薪资爆料：** 结构化表单（年度总包、月度Base、绩效、期权、社保公积金等）
- **公司评价：** 五维星级打分 + 优缺点文字评价
- **发布系统：** UGC匿名发布，支持面经/薪资/评价三种内容类型
- **个人中心：** 我的发布/收藏/点赞/评论，实用工具（薪资计算器、公司对比、职业路径规划）

**后端（Java SpringBoot）：**
- 完整RESTful API接口（60+接口）
- MyBatis-Plus + MySQL 8.0 数据持久化
- 点赞/收藏/评论/举报完整互动体系
- 排行榜算法（热度/真实度/时间/薪资）
- 敏感词过滤与内容审核机制
- 文件上传与静态资源服务

**技术架构：**
```
微信小程序 (WXML + WXSS + JS)
        ↓
   RESTful API
        ↓
Java SpringBoot + MyBatis-Plus
        ↓
     MySQL 8.0
```
### ④用 TRAE SOLO 实现的过程

**任务拆解：**

项目包含前端小程序和后端服务两大模块，按照以下优先级实施：

| 优先级 | 模块 | 主要任务 |
|--------|------|----------|
| P0 | 项目架构搭建 | 目录结构、配置文件、技术选型 |
| P0 | 数据库设计 | ER图、建表语句、索引优化 |
| P0 | 核心页面开发 | 首页、公司详情、内容详情 |
| P1 | 发布功能 | 三种内容类型的发布表单 |
| P1 | 用户中心 | 登录、头像、个人资料 |
| P1 | 后端核心接口 | CRUD、点赞收藏评论 |
| P2 | 实用工具 | 薪资计算器、公司对比、职业路径规划 |
| P2 | 审核与合规 | 敏感词过滤、免责声明 |

**用的 SOLO 能力：**

1. **代码生成与重构** - 快速生成Controller、Service、Mapper三层架构代码
2. **错误诊断与修复** - 定位并修复WXML编译错误、API 404/500错误、数据渲染问题
3. **多文件协同修改** - 保持前后端接口一致性，批量更新相关文件
4. **代码审查与优化** - 发现潜在问题（如空指针、数据类型不匹配）
